Technical Deep Dive

เจาะลึกกระบวนการทำงานของระบบประมวลผลข้อมูลสุขภาพผู้ป่วยที่ได้รับผลกระทบจากฝุ่นละอองขนาดเล็ก (PM2.5)

ลำดับการประมวลผลข้อมูล (Data Pipeline Steps)

1. สกัดข้อมูลดิบ (Data Extraction)

รันผ่าน BashOperator เพื่อดึงข้อมูลรายงานจากระบบ HDC (Health Data Center) กระทรวงสาธารณสุข

HDC Web Interface Selenium Automation Raw CSV Output
Business Logic
  • ดึงข้อมูลย้อนหลังปี 2567, 2568, 2569
  • ครอบคลุม 77 จังหวัด ทั่วประเทศไทย
  • เลือกกลุ่มโรค 01-05 (ที่เกี่ยวข้องกับมลพิษ)
Runtime & Logs
  • Log File: scripts/scraping.log
  • Execution Time: 3-5 ชั่วโมง (ขึ้นอยู่กับความเร็วเว็บ)
  • Retry: 1 ครั้งกรณี Network Timeout

2. ปรับโครงสร้างข้อมูล (Data Transformation)

นำข้อมูลดิบจากขั้นตอนที่ 1 มาทำการเปลี่ยนจากรูปแบบ Wide เป็น Long Format เพื่อให้ง่ายต่อการวิเคราะห์ (SQL Friendly)

กระบวนการภายใน (Internal Processing)
  • กำจัดอักขระพิเศษและช่องว่างส่วนเกิน
  • Melt Columns: Week1-52 -> Time dimension
  • Mapping รหัสจังหวัดให้เป็นมาตรฐานเดียวกัน
  • Output: hdc_merged_long_[ปี].csv

3. รวมชุดข้อมูลสมบูรณ์ (Data Consolidation)

ขั้นตอนสุดท้ายในการรวมข้อมูลทุกปีเข้าเป็นไฟล์เดียว และทำการส่งสรุปผลการทำงาน

Final Artifacts
  • Final Output: scripts/hdc.parquet ( optimized for DuckDB )
  • Notification: แจ้งเตือนสถานะการรัน Pipeline ลง Discord

Technical Stack & Dependencies

Platform Apache Airflow 3.0.2
Language Python 3.12
Automation Selenium 4.20.0
Browser Chromium (Headless)
Data Lib Pandas 2.2.2

Troubleshooting (กรณีเกิดปัญหา)

  • หาก scrape_hdc_data ล้มเหลว: ตรวจสอบ scripts/scraping.log เพื่อดูว่าหน้าเว็บ HDC มีการเปลี่ยนโครงสร้างหรือไม่
  • ปัญหา Timeout: การสแครปข้อมูลใช้เวลานาน หากเกิด Timeout ให้ตรวจสอบความเร็วของอินเทอร์เน็ตเซิร์ฟเวอร์
  • ปัญหา Memory: ไฟล์ CSV มีขนาดใหญ่ หากเกิด Out of Memory ให้ตรวจสอบทรัพยากรของ Docker Container
