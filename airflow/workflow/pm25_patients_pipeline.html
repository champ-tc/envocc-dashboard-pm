Workflow: pm25_patients_pipeline_dag

คำอธิบาย: Pipeline สำหรับการรวบรวมข้อมูลผู้ป่วยที่เกี่ยวข้องกับฝุ่น PM2.5 โดยครอบคลุมขั้นตอนการ Scraping ข้อมูลจากระบบ HDC, การเตรียมข้อมูล (Merging) และการรวมข้อมูลเป็นชุดเดียว (Concatenation)

1. ภาพรวมลำดับการทำงาน (Workflow Sequence)

scrape_hdc_data
➜
merge_hdc_data
➜
concatenate_hdc_data

2. รายละเอียดแต่ละ Task

Task 1: scrape_hdc_data

สคริปต์ที่รัน: scraping.py

หน้าที่: เข้าไปที่เว็บไซต์ HDC (MOPH) เพื่อดึงข้อมูลรายงานสถิติจำนวนผู้ป่วยรายจังหวัด โดยใช้ Selenium และ Chromium ในโหมด Headless

เงื่อนไข: ใช้เวลาทำงานได้สูงสุด 4 ชั่วโมง (14,400 วินาที) มีระบบตรวจสอบ Dependency (pandas, selenium, ฯลฯ) ก่อนเริ่มงาน

Task 2: merge_hdc_data

สคริปต์ที่รัน: merged.py

หน้าที่: นำไฟล์ข้อมูลดิบที่ได้จากการ Scrape มาทำการจัดโครงสร้างข้อมูลใหม่ (Pivot/Reshape) ให้อยู่ในรูปแบบ Long Format ที่พร้อมสำหรับการวิเคราะห์

เงื่อนไข: ทำงานหลังจาก Task แรกสำเร็จเท่านั้น มี Timeout 10 นาที

Task 3: concatenate_hdc_data

สคริปต์ที่รัน: cell.py

หน้าที่: รวมไฟล์ข้อมูลที่ประมวลผลแล้วจากหลายปีเข้าด้วยกันเป็นไฟล์สุดท้าย (Final Dataset) เพื่อใช้ในการแสดงผลบน Dashboard

เงื่อนไข: เป็นขั้นตอนสุดท้ายของ Pipeline มี Timeout 5 นาที

3. เงื่อนไขและกำหนดการ (Execution Policy)

หัวข้อ รายละเอียด
กำหนดการ (Schedule) Production: 03:00 น. ของทุกวัน (0 3 * * *)
Development: ไม่มีการรันอัตโนมัติ (Manual Trigger Only)
การลองใหม่ (Retry) หากล้มเหลว จะพยายามรันใหม่ 1 ครั้ง หลังจากผ่านไป 5 นาที
การแจ้งเตือน (Notifications) ส่งข้อความผ่าน Discord Webhook (pm25_pipeline) เมื่องานสำเร็จหรือล้มเหลว
Environment รันผ่านระบบ Subprocess โดยมีการตั้งค่า PYTHONUNBUFFERED=1 เพื่อให้เห็น Log แบบ Real-time

4. ข้อควรระวัง

  • Task scrape_hdc_data ใช้ทรัพยากรสูงและใช้เวลานาน ต้องตรวจสอบพื้นที่จัดเก็บไฟล์ Log และไฟล์ CSV ชั่วคราวสม่ำเสมอ
  • หากโครงสร้างหน้าเว็บ HDC เปลี่ยนแปลง สคริปต์ scraping.py อาจทำงานผิดพลาด
  • ไฟล์ผลลัพธ์สุดท้ายจะถูกเก็บไว้ในโฟลเดอร์ dags/scripts/
