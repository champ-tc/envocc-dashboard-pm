# AGENTS.md: Global System Rules

## General Mandates
- **Cross-Service Integrity**: Before modifying one service (e.g., `web`), consider if it depends on data generated by another (e.g., `airflow`).
- **Database Consistency**: 
  - `postgres` (internal port 5432): Airflow metadata and Celery result backend.
  - `postgres-etl` (host port 15432, container port 5432): Application users, metadata, and processed data. Check both Drizzle and Airflow consumers before changing schemas.
- **Port Management**: 
  - `3000`: Web Dashboard
  - `8080`: Airflow Webserver
  - `80/443`: Nginx Proxy

## System Maintenance
- **Docker**: Always check `docker-compose.yml` before adding new services or volumes.
- **Environment Variables**: All services share the root `.env` file. Never commit `.env`.
- **Secrets**: API keys and passwords must be stored in `.env`.

## Service-Specific Rules
- **Web**: Refer to `web/AGENTS.md`.
- **Airflow**: Refer to `airflow/AGENTS.md`.
- **Nginx**: Configuration is located in `nginx/nginx.conf`. Ensure path routing (`/` vs `/airflow`) is preserved.

## Data Workflow Safety
1. **Source Data**: Scripts in `airflow/dags/scripts/` are the "Source of Truth" for data processing.
2. **Runtime Output Files**: Airflow writes CSV/Parquet files to the shared `duckdb-data-volume` at `/opt/airflow/data`; Web reads the same volume at `/app/public/duckdb`. Do not edit runtime outputs manually; update the Airflow pipeline.
3. **Image Seed Files**: Files committed under `web/public/duckdb/` and `airflow/dags/scripts/` seed a new volume during initialization. Keep seed schemas compatible with runtime outputs.
4. **DuckDB**: Reflect schema changes in every affected query under `web/src/app/dashboard/`, not only the HDC dashboard.
