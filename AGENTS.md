# AGENTS.md: Global System Rules

## General Mandates
- **Cross-Service Integrity**: Before modifying one service (e.g., `web`), consider if it depends on data generated by another (e.g., `airflow`).
- **Database Consistency**: 
  - `postgres` (port 5432): Do not modify tables managed by Airflow or Drizzle without checking both schemas.
  - `postgres-etl` (port 15432): Primarily for data storage; verify Airflow scripts before changing table structures.
- **Port Management**: 
  - `3000`: Web Dashboard
  - `8080`: Airflow Webserver
  - `80/443`: Nginx Proxy

## System Maintenance
- **Docker**: Always check `docker-compose.yml` before adding new services or volumes.
- **Environment Variables**: All services share the root `.env` file. Never commit `.env`.
- **Secrets**: API keys and passwords must be stored in `.env`.

## Service-Specific Rules
- **Web**: Refer to `web/AGENTS.md`.
- **Airflow**: Refer to `airflow/AGENTS.md`.
- **Nginx**: Configuration is located in `nginx/nginx.conf`. Ensure path routing (`/` vs `/airflow`) is preserved.

## Data Workflow Safety
1. **Source Data**: Scripts in `airflow/dags/scripts/` are the "Source of Truth" for data processing.
2. **Output Files**: Files in `web/public/duckdb/*.csv` or `*.parquet` are generated by Airflow. **Do not modify these manually**; update the Airflow pipeline instead.
3. **DuckDB**: Ensure any schema changes in `.parquet` files are reflected in the DuckDB queries within `web/src/app/dashboard/hdc/actions.ts`.
